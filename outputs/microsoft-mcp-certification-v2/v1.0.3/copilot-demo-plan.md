# Genuine Copilot Studio capture plan

Use the final name "CertScore Web Privacy Scanner" and the supplied canonical icon. All screenshots and recordings must come from the actual connected Copilot Studio interface; do not fabricate a connection or tool output. Keep tokens, client secrets, account identifiers unrelated to the demo, and sensitive URL values out of captures.

Prerequisite: establish the authentication flow agreed with Microsoft for the submitted /mcp/microsoft endpoint. Do not substitute the public Light endpoint and present it as validation of the submitted endpoint.

## Screenshots

Capture at 1366 x 768 with readable UI and an embedded caption; use PNG under 1,024 KB. Reserve caption space without obscuring important controls or outputs.

1. "Connect CertScore Web Privacy Scanner" - actual connected MCP tool configuration showing product identity and the four tools, with no secrets.
2. "Scan a public website from your agent" - real test conversation requesting a scan of the publisher-owned https://certscore.ai/ and a visible request/status result.
3. "Review observed privacy signals" - completed response with actual cookie/tracker/consent/policy or TLS observations and any coverage limits. Use only observations the scan returned.
4. "Inspect evidence and open the report" - real evidence retrieval and report link. Explain paginated evidence without suggesting each page is a new scan.

## Short video

Aim for a clear 90-150 second demonstration. This is a suggested length, not a Microsoft policy requirement.

- Introduce the product and free usage-limited public-site scope.
- Show the genuine Copilot Studio connection and available tools.
- Ask: "Use CertScore to scan https://certscore.ai/. Follow the returned retry guidance until the scan is terminal, then summarize the observed privacy signals and coverage limits and provide the report link."
- Show real tool execution. If a recent report is reused, say so. If waiting is shortened in editing, visibly label the elapsed-time cut.
- Ask for supporting report evidence and show the returned evidence/next-page behavior if applicable.
- Close with the support/documentation links and the distinction between observed review signals and legal conclusions.

Do not promise a finding for a particular site, label unknown evidence as clean, or display mocked tool outputs as genuine functionality. Retain original captures for reviewer questions.
